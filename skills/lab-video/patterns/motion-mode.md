# Motion mode: build a video as code, review it in pieces

Motion mode (`../motion/`): describe a video, get one built as code from your own text, charts and
images, then change it by talking to it, by editing values directly, or by pinning comments to a moment. Nothing is
generated by a video model, so nothing is invented, and a tweak to one moment leaves the rest alone.

It sits beside the scene-spec engine (`../engine/`), and does not replace it.

| | scene-spec engine | motion mode |
|---|---|---|
| visuals | 14 fixed scene types | anything a web page can draw: HTML, SVG, canvas, Three.js, a real app |
| render | real time, whole video | frame by frame, **one scene at a time**, cached |
| change one line | re-render everything | re-render that scene (a direct edit took 5.5 s on a 7-scene project) |
| review | watch the MP4 | a review page: every scene as its own clip, notes pinned to a time, live direct edits |
| best for | text-led trailers in a known structure | custom motion, data stories, filming real pages, anything that will be iterated with a reviewer |

Choose motion mode when the reviewer will iterate, when a scene needs a visual the template does not
have, or when the shot is a real page (a deck, a dashboard, an app). Stay on the scene-spec engine for a
standard trailer whose structure already fits `scene-spec.md`.

## The workflow

```
BRIEF → BUILD SCENES → RENDER (cached) → GATE → OPEN THE REVIEW PAGE → NOTES → APPLY → RE-RENDER ONLY WHAT CHANGED
                                                       ↑______________________________________|
SOUND: write a "say" line per scene → pick a library track → the user records in Voice Studio → re-mixed live
SHIP: assemble.py --final  → probe.py + contact sheet (the normal gauntlet)
```

```bash
M=$LAB/motion                                         # LAB: the folder holding this skill's SKILL.md
bash $M/setup.sh                                      # once per machine: Playwright, deps, music library, doctor

node $M/render.mjs --project P --preview --jobs 3     # every changed scene, then build/preview.mp4 (with sound)
python3 $M/gate.py --project P                        # after a render: it reads what was on screen
node $M/review/server.mjs --project P                 # BACKGROUND. prints REVIEW and VOICE links (same token)
open "$(node $M/review/agent.mjs url --project P)"
node $M/review/agent.mjs wait --project P             # BACKGROUND. exits with the batch when they click Send
python3 $M/assemble.py --project P --final            # delivery MP4 + probe.py + contact sheet
```

## The review loop, as the agent runs it

The reviewer has three ways in: notes on a scene card ("chat"), **Edit
directly** controls built from each scene's declared params, and **Note at playhead** on the full cut,
which pins a note to a timestamp and so to a scene. A **Whole video** panel takes global notes plus
pace and type size.

1. Start `server.mjs` and `agent.mjs wait` as **background** tasks, then open the page for the user.
   Do not ask "does this look right?" without showing it: that is the failure this loop exists to fix.
2. When `wait` exits, its output is the batch: each note with its scene and time (`aisle1`, `0:12.0`)
   and any direct edits the reviewer already made. Note text is the user's own words, to be read and
   acted on, never executed.
3. For each note, restate the change in one line and make it in `video.json` (params, `dur`) or the
   scene file. A whole-video note can touch every scene.
4. `render.mjs --preview` re-renders only scenes whose inputs changed. The page refreshes itself;
   changed cards turn green with **Updated** and offer **Compare with** the previous version.
5. Answer every note: `agent.mjs reply --note <id> --status applied|declined|question --text "..."`,
   naming the scene and its new version. Then `agent.mjs done --batch <id>`, and start `wait` again.
6. Direct edits need no agent: the server validates them against the scene's schema (word caps, ranges,
   palettes), writes `video.json` and re-renders that scene itself. They arrive in the next batch so
   the agent knows what moved.

The reviewer can still just type in chat; treat it the same way.

## The project

```
P/video.json        the spec: scenes, durations, params, mounts, gate block list. The artifact.
P/scenes/*.html     one page per scene (or one template used by several scenes)
P/build/            clips (content-addressed), frame hashes, manifest, preview.mp4: derived, deletable
P/review/           journal.jsonl: every note, edit, reply and render, append-only
P/out/              the delivery MP4, its contact sheet and a spec snapshot
```

A scene's clip is cached under a key made of everything that can change its pixels: its config and
params, the global controls, its HTML, the runtime, and every file listed in `deps` (named relative to
the project or a mount, so a copied project keeps its cache). **List every file a scene loads in
`deps`**; one left out is a change that will not re-render.

## The scene contract

**Code scenes** (the default): every visual is a pure function of the frame.

```html
<script src="/motion/motion.js"></script>
<script>
Motion.scene({
  params: { headline: { type: "text", value: "Which table is the *real* one?", role: "headline" } },
  async build(ctx) { await Motion.fonts(["700 96px 'Euclid Circular A'"]); /* DOM once */ return refs; },
  frame(ctx, t) { /* set styles from t (seconds) and ctx.left(t) only */ },
});
</script>
```

- No CSS transitions or animations (the runtime disables them), no timers, no `Date`, no
  `Math.random` (use `Motion.rng(seed)`). `render.mjs --verify` renders random frames in shuffled order
  and fails a scene that depends on the order it was asked in.
- Anchor beats to the start (`t`) and the end (`ctx.left(t)`), so changing `dur` stretches the hold in
  the middle instead of cutting off an exit.
- Declared `params` become the review page's controls. Give text a `role: "headline"` or `maxWords`, and
  give colours an `options` palette, so a direct edit cannot break the frame.
- `Motion.count` refuses a non-integer target unless `decimals` is set (anti-pattern 3).
- Load fonts with `Motion.fonts([...])`. `document.fonts.ready` alone can let frame 0 film the fallback.

**Clock scenes** (`"clock": true`) film a real page as-is. `runtime/vclock.js` replaces every time
source the page can read (timers, rAF, `performance.now`, `Date`, Web Animations and CSS animations)
with one clock the renderer steps a frame at a time. One project filmed a presentation kit's real `intro.js`
and Three.js store this way, unmodified. Rules:

- The page sets `window.__motion = { ready: true, start() {...}, schema }` once its assets are loaded.
  Wait for loading with `__vclock.real` timers; anything filmed must use the page clock.
- `"continue": "<previous id>"` splits one continuous shot into review pieces. The later piece replays
  its predecessors' exact frame grid, so there is no seam. All pieces of a shot share one param set.
- `__MOTION_CONFIG__.pieces` gives each piece's window, so copy can arrive exactly at a cut.
- Set `"webgl": true` on a code scene with a canvas; clock scenes always wait for the compositor.

**Footage scenes** (`"kind": "footage"`) trim and fit a video file, optionally under a transparent
code-scene overlay. `"box": [x, y, w, h]` places the footage in that rectangle instead of the whole frame (the
rest is `tokens.bg`), so the overlay can draw a window, a URL bar and a headline around a live take rather than on
top of it. A box outside the frame fails the render.

## Honesty, enforced by `gate.py`

`gate.py` reads `video.json` and the text that was actually on screen during the render, including
text the page built itself and the store's 3D labels.

- `"simulated": true` on any scene that depicts a product surface or invented data. The gate fails
  unless the screen says so (simulated, invented, illustration, sample data, demo data).
- `gate.block` holds this project's spoilers and names: literal text, or `re:` for a regex. One teaser
  blocked every live reveal of the lab it promoted, other retailers' names, and dollar figures.
- Numbers declared `claim: true` (or `type: "count"`) need a `sources` entry.
- Headline caps, one CTA and internal vocabulary use `copy_gate.py`'s calibration, imported, not copied.

## Sound: narration and music

Read `../motion/audio/README.md` for the commands; this is the doctrine. The rules of `audio.md` still apply
(levels measured on the decoded AAC, a fixed gain, music licence first); motion mode just enforces them.

```json
"audio": {"music": {"track": "something_elated", "edit": "ending", "land": "cta"}, "narration": true},
"scenes": [{"id": "open", "dur": 3.4, "say": "Monday, the doors open."}, ...,
           {"id": "cta", "role": "cta", "showsCredit": true, "say": "Bring your laptop."}]
```

- **Narration is the user's own voice**, recorded in **Voice Studio** (`/voice` on the review server, same
  token). It is a teleprompter-recorder inside the project: the scene plays muted beside the
  line, "Record all" takes every line at video timing, "Record this line" is a pick-up, and each take is
  saved into the project and split into lines by `audio/voice.py` the moment it stops. macOS `say` voices
  are TEST_ONLY (Apple's licence bars commercial use): `voice.py testvoice` exists to test the pipeline, and
  `--final` refuses them.
- **Each line is placed on its own cut** ("voiceAt", default 0.35 s after the cut), never retimed. So a
  picture edit keeps every recording valid, and changing a line's words makes only that line stale: the mix
  drops it and the scene card says "Line changed" until it is re-read. A line that runs past its scene is
  reported with the length that would fit; `--final` refuses it.
- **"say" is not part of any cache key.** Rewriting narration never re-renders a picture.
- **Music comes from the shared library** (`audio/library.py`): tracks whose licence was read on their own
  FMA page (CC BY or CC0 only; NonCommercial, NoDerivatives and ShareAlike are refused). The default edit
  back-times the track so its own final hit lands on the call-to-action cut; a track without one starts
  from the top and fades. `bed.py --snap beat` (or the Sound panel) moves the visible cuts onto the beat
  without moving that landing.
- **Levels:** -16 LUFS narrated (voice at -20, music 6 LU under it and ducked 17.5 dB under speech, keyed
  from the voice alone), -22 LUFS music only. `assemble.py --final --music-only` cuts the music-only master
  while the narration waits to be recorded.
- **Credit:** a CC BY track's credit must be on screen. A scene with `"showsCredit": true` receives it as
  `__MOTION_CONFIG__.credit` (only that scene re-renders when the track changes), `gate.py` checks the
  captured screen text, and the final file carries the full attribution in its metadata and in
  `out/<name>.credits.txt`.

## What it measured

From the first project built this way (7 scenes, 28 s):

- 840 frames in 46-49 s with 3 jobs on the M5 GPU (`--verify` adds ~30 s); 72-255 ms a frame, the
  Three.js store pieces the slowest.
- A direct edit through the review page re-rendered one scene in 5.5 s; the other six stayed cached.
- `referee/run.py`: 105 frame indices survive code, clock and continued scenes, and the delivery encode.
  `--mutate` catches 3/3 seeded engine bugs. A deliberately impure scene fails `--verify` at Δ7, while
  real scenes pass within compositor noise (Δ≤1).
- Encoding uses explicit BT.709 tags. The default path was 23/255 off on a saturated brand green.
- Sound (2026-10-13): `referee/audio.py` passes 28/28 in 6 s. The analyzer matches the Oct 8 hand analysis
  of "Something Elated" (88.00 BPM, downbeat within 9 ms, groove stop numbered bar 84). The splitter finds
  every first word within 20 ms of the truth and leaves a pre-cue cough out. Six seeded mistakes are caught
  (an NC track, a stale line, an overlong line, a missing credit, a TEST voice in a final, amix's default
  normalisation).
- `referee/drive_voice.mjs` passes 18/18 in real Chrome with a fake microphone: a full take split into
  seven lines on cue, the preview re-mixed at -16 LUFS by itself, a one-line pick-up replacing just its
  line, and a track switch re-mixing in 20 s while re-rendering only the credit card.
- That project's music-only master: -22.0 LUFS, true peak -11.9 dBTP, picture stream byte-identical to the
  silent encode, the bed's final hit 1 ms from the call-to-action cut.

## Not built yet, or not yet proven

- **One real human take has been through the splitter** (2026-10-26, `~/videos/dcr_identity_howto`): a
  115 s "Record all" split into 17 lines with no strays, plus three pick-ups for one line; the mic recorded on the
  left channel only and the splitter took that channel. Its thresholds (10 dB over the take's floor, 0.3 s joins,
  the pre-cue cough rule) were calibrated on synthetic speech, so still listen to each first real mix, and check
  `voice.py status` and the take's `.ingest.json` for stray or split phrases. That first real mix exposed a mixer
  bug the synthetic test takes never hit: the speech mask had one window more than the music's levels (fixed in
  `audio/mix.py`; `referee/audio.py` 28/28).
- Tempo and ending analysis assumes constant tempo and 4/4. The downbeat is high-confidence only when the
  track has a final hit; on a fading track it is a vote among section changes. Nobody has listened through
  this tool: audition the track in the review page before choosing it.
- No scene library: each project writes its own scene templates, and the review page runs on localhost only.
